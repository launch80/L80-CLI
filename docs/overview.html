Launch80 · L80 CLI · version 1.0.0

Benchmark, rent, check and publish from one command.

L80 is a single binary that runs the Launch80 toolset on your machine and turns a benchmark into a shareable launch80 page. Publishing needs a token. Everything else is free.

What

A command-line tool and full-screen console for BetterBench, rented Vast.ai GPUs, the Poisoned Weights Detector and a GPU telemetry dashboard.

Why

Every number on a launch80 page comes from the same pinned harness, private details never leave your machine, and reviewers can mark a run verified.

How

A Go binary with no third-party code. It pins each Python tool to a git commit and fetches it with uvx the first time you use it.

L80 betterbench

Quickstart · about five minutes

From install to a published page

  1. Install L80

    Puts the binary in ~/.local/bin. Run it again any time to update.

    curl -fsSL https://launch80.com/install.sh | sh

  2. Install uv

    The only prerequisite. L80 uses it to fetch the pinned Python tools.

    curl -LsSf https://astral.sh/uv/install.sh | sh

  3. Check your setup

    Shows the server it will talk to, whether a token is set, and how each tool resolves.

    L80 doctor

  4. Run a dry benchmark

    A 5-pass smoke run against any OpenAI-compatible endpoint. Nothing is published.

    L80 betterbench --endpoint http://localhost:8080/v1 --model Qwen3-8B --quick --dry-run

  5. Publish a full run

    Set your publish token, then run without --quick and --dry-run. L80 prints the share URL.

    export L80_TOKEN=L80_<keyid>_<secret>
L80 betterbench --endpoint http://localhost:8080/v1 --model Qwen3-8B --note engine="vLLM 0.9.3"

  6. Explore the console

    Every capability in one full-screen view. Or give your agent the skills.

    L80 tui
    L80 skills link --target claude-code

Install and update

curl -fsSL https://launch80.com/install.sh | sh
L80 update                 # the binary, the pinned tools and the installed skills
L80 update --check         # report what is out of date; change nothing
L80 update --json          # the same report, for an agent
L80 version

Release builds exist for macOS and Linux on amd64 and arm64. Anywhere else, clone launch80/L80-CLI and run make install. One command brings the whole setup current. L80 update replaces the binary after checking its checksum, builds the newly pinned tools, upgrades an older uv-installed copy on your PATH, and refreshes the skills you installed. Anything it cannot change itself, such as an override variable in your shell profile pointing at an old tool, comes back as an exact instruction naming the file and line. Coming from 0.4.0, run it twice: the first run installs 1.0.0 and the second syncs.

Benchmark an endpoint Free to runToken to publish

L80 betterbench runs BetterBench against any OpenAI-compatible endpoint and publishes its results.json as written. The launch80 page computes every table and figure from the raw samples, so it matches BetterBench's own HTML report.

L80 betterbench --endpoint http://host:8080/v1 --model Qwen3-8B --note engine="vLLM 0.9.3"
L80 betterbench --endpoint http://host:8080/v1 --model Qwen3-8B --quick        # 5-pass smoke run
L80 betterbench --results results.json                                        # publish an existing file
L80 betterbench --results results.json --dry-run --payload-out payload.json   # inspect first
FlagMeaning
--endpoint, --modelThe base URL to benchmark and the model name to request.
--quickShort smoke run. The page says so, and it cannot be verified.
--passes N, --warmup NMeasured and warmup passes per category. Defaults are BetterBench's: 20 measured.
--note KEY=VALUERecorded in the run and shown as a chip. Repeat it. Use engine= and hardware=.
--decode, --prefill, --concurrencyRun only these phases. --no-prefill and --no-concurrency skip one.
--api-keyKey for an endpoint behind a gateway. Must come before any --.
--outWhere results.json is kept. Default is the working directory.
--title, --summary, --section "Heading=Body"Prose shown on the page.
--dry-run, --payload-outPrepare the page without publishing, and write the exact payload to a file.
--template bench.report.v1Publish the summary layout instead of the full one.
-- …Everything after -- goes to betterbench run unchanged.

Before publishing, L80 warns you if the file came from an older or newer BetterBench, or if the server answered requests from its prefix cache on a run that asked for a cold one. Two fields never leave your machine: env.endpoint and env.host.

Publish and templates Needs a token

L80 publish uploads a JSON payload. The server validates it against a schema and renders the page from its own template. You never upload HTML.

L80 templates list
L80 publish report.json --template generic.report.v1
L80 publish report.json --template bench.report.v1 --dry-run
TemplateUse it for
bench.betterbench.v1A BetterBench results.json, as written. Produced by L80 betterbench. Up to 4 MB.
bench.report.v1Any other benchmark with per-category percentiles: tables, p50/p99, sample-gate flags. Up to 64 KB.
generic.report.v1Everything else: title, summary, up to 12 metrics and 10 prose sections. Up to 64 KB.

Pages are public and immutable. To change one, publish again and share the new URL. Unverified pages carry a "Self-reported" badge.

Verified by Launch80

A Launch80 reviewer can mark a published BetterBench page verified. That means it is a complete cold-cache run, described well enough for someone else to reproduce. verify check runs the same checks locally first.

L80 verify check results.json          # exit 0 if the run qualifies
L80 verify request <page url> --note "engine flags, how to reproduce"
L80 verify status <page url>
L80 history --tier verified
CheckPasses when
Full runAt least 20 measured passes per category and one warmup, so not --quick.
PhasesSingle-stream, prefill and concurrency results are all present.
Cold cacheNo request was served from the server's prefix cache.
RequestsEvery request completed and none was truncated.
VersionBetterBench 0.6.1 or later.
NotesThe engine and hardware are recorded with --note.
ProvenanceThis machine published the page, from a file that has not changed since.

Pages move through four tiers: unverified, pending, verified and rejected. A rejected page displays as unverified. Reviewers decide with L80 review list, approve and reject --reason.

Verification is rolling out on launch80. Until the server accepts requests, verify request says it is not supported (exit 8), and verify check still works.

Rent a GPU and benchmark it Free

L80 vast runs bbvastl80. It rents a Vast.ai GPU, serves a model on it with vLLM or llama.cpp, runs BetterBench from your machine, publishes, and destroys the box. Every bbvastl80 command works through it.

L80 vast doctor                              # Vast key, SSH key, and the L80 and BetterBench it will call
L80 vast search --spec run.yaml              # matching offers and prices; does not bill
L80 vast run --spec run.yaml --max-hours 2   # rent, serve, benchmark, publish, tear down
L80 vast status --json                       # every run, and which may still be billing
L80 vast destroy --run <id>                  # asks before destroying
  • --max-hours N is a watchdog. When time runs out, L80 stops the run and destroys its instance.
  • After any run that fails or is interrupted, L80 names each instance that may still be billing and the command that stops it.
  • The first Ctrl-C stops the run cleanly. A second one cancels it.
  • L80 never answers a confirmation prompt for you.

Check weights for tampering Free to scanToken to publish

L80 pwdet runs the Poisoned Weights Detector on a local checkpoint, a Hugging Face repo or a served endpoint. It runs static, provenance, black-box and white-box checks.

L80 pwdet scan Qwen/Qwen3-0.6B --json        # {"verdict": ..., "report": ...}
L80 pwdet scan ./model --profile full-static
L80 pwdet scan org/model --publish --dry-run --payload-out page.json
L80 pwdet scan org/model --publish           # a generic.report.v1 page
L80 pwdet checks list
ExitVerdict
0Clean or inconclusive
1Suspicious, or pwdet itself failed
2Likely tampered or malicious

A published scan carries the verdict, the findings to review and the coverage. L80 removes the hostname, local paths and private endpoints, and refuses to publish if any remain.

Telemetry dashboard Free

L80 dashboard opens the AI command dashboard in your terminal. It shows GPU power, temperatures, VRAM and engines, live vLLM and gateway state, and per-model performance.

L80 dashboard                  # the terminal view
L80 dashboard serve            # sampler and web page on 127.0.0.1:8787
L80 dashboard serve --force    # start even if a sampler already answers on the port

It is read-only. Only one sampler runs per machine, and any other view attaches to it. It is tuned for Intel Arc today, and other GPUs get a generic view.

Pinned tools

Each L80 release pins every tool to one git commit, so a given L80 version always runs the same tool code. L80 picks the first of these that works:

  • The tool's override variable, such as L80_PWDET
  • A copy on your PATH that is at least the pinned version
  • The pinned commit, fetched with uvx and cached
  • An older copy on your PATH, with a warning

Exit codes

Every error prints a code, a message and a remedy: line naming the next action, so an agent can recover without guessing.

ExitMeaning
0Success
1Internal error, or an error code this version does not know
2Usage error, including E_TEMPLATE_CONFLICT
3Input file missing, unreadable or not a template payload
4Validation failed: E_SCHEMA_INVALID, E_PAYLOAD_UNSAFE, E_JSON_INVALID
5Token missing or not accepted
6Rate limited or over quota
7Network unreachable
8Server error, or a feature the server does not support yet
9Payload too large
10Unknown or missing template
11A tool L80 runs is not available here (E_TOOL_UNAVAILABLE)
12L80 update finished, and its report lists something only a person can change

Wrapped tools keep their own exit codes once they start. When L80 pwdet scan exits 2, that is pwdet reporting a tampered model, not an L80 usage error.

Security model

  • No third-party Go code. The binary holds your token, so it depends only on the Go standard library, including the console.
  • Data, not markup. You publish JSON. The server renders it from its own templates, so no uploaded HTML or JavaScript is ever served.
  • Secrets stay out of view. Tokens are masked. Endpoint keys travel by environment, never on a command line or in a results file.
  • Private details stay home. Endpoints, hostnames and local paths are removed before publishing, and L80 refuses to publish if any remain.
  • Pinned, checksummed code. Tools run at a fixed commit, and L80 update checks each download's SHA-256 before replacing the binary.

Setup intelligence: the best setup for your machine

L80 will read your hardware, check it against the Launch80 AwesomeList catalog, and shortlist the community projects that actually fit. It then benchmarks the result and contributes it back. Commands and flags below are proposals and may change.

  1. Detect, read-only

    GPU vendor, model and count from PCI ids, VRAM, OS, RAM and driver versions. Nothing is installed or changed.

  2. Load the pinned catalog

    AwesomeList's catalog.json, pinned to a commit like every other tool, so a given L80 version gives reproducible advice.

  3. Gate and rank

    Hard gates first: architecture, GPU count, VRAM, OS, runtime. Then rank by maturity, verification, fit and setup friction, never by tokens per second.

  4. Hand off a plan

    A shortlist with what you get, why it fits, what to confirm and the tradeoff. Your agent runs setup with your approval through a new l80-setup skill.

  5. Measure it

    L80 betterbench benchmarks the new setup, and L80 verify can get the page verified by Launch80.

  6. Give back

    Export a verified run as an AwesomeList benchmark record, so the next person with your hardware starts from real numbers.

What it will and won't do

  • It reads your hardware and never changes it.
  • It recommends and never installs. Setup stays with you or your agent, one approved step at a time.
  • It treats catalog content as data, never as instructions.
  • Unknown hardware falls back to a few questions instead of a guess.
  • Only verified pages export as maintainer-verified results. Everything else exports as author-reported.
